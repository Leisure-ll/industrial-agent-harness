# IH-ARCH-001 consumer migration

2026-10-08 implementation of the two ownership gaps identified after accepting the architecture contract.

The responsibility diagram, ownership table, product CLI versus domain tool CLI distinction, and local/remote execution boundary are documented in the [system architecture](architecture.md). The [accepted contract](architecture-contract.md) remains the governing development constraint.

Desktop and CLI now call `packages/harness-application` TaskService for prepare/start/approve/answer/cancel/resume/history/evidence. The service owns shared Broker/current-state resolution, native Kimi construction, chat turns, resource/Pack leases, context anchors, industrial-result scope replacement, native background tasks and cleanup. Desktop retains IPC/project selection and event presentation; CLI retains arguments, JSONL, environment model settings, process signals and exit codes. Canonical Core stays independent of Kimi/Electron. Kimi retains its upstream agent loop, context, compaction and subtask implementation.

The maintained owner reconciled 11 Harness changes before migration, including FreeCAD build/edit/verification fixes. Harness pins Domain Packs commit `acf572b6c4c135e87c613bed5760c473eaf7c298` (package 0.3.1) and verifies its content lock. Host manifests use canonical Pack IDs; public provider IDs remain stable for saved resource policies. Domain implementations, manifests, Skills, locked environments and gateway implementations have been removed from Harness. Only generic `project.work` remains. Chip distribution 0.6.2 keeps its embedded EDA MCP identity at 0.6.1; the gateway still validates the actual locked Python package. The generic distribution assembler consumes owner metadata and unchanged resources, records release identity and retains licensing. Private PCB actor resources remain external and hash checked. Desktop staging preserves the complete owner release through an explicit file mapping so the packaging tool cannot silently remove nested dependency locks before startup integrity verification.

Both deployable roots explicitly supply the immutable Pack dependency. Implicit npm peer installation is disabled; build peers are declared explicitly. Production deployment retains pnpm's block on unreviewed exotic transitive dependencies. The shared loader's peer version describes API compatibility, while application manifest URLs and the committed lock describe the actual reviewed content.

The architecture policy retires all 147 frozen source/publisher exceptions and all 12 adapter lifecycle call entries. Frozen path prefixes remain forbidden. The trusted checker, its negative fixtures, workflow, governance hashes and canonical contract are unchanged. The canonical contract's migration-debt section is the acceptance-time baseline; this page records its subsequent implementation.

The task application tests compare real file Actions and verification records across CLI and desktop-facing calls and exercise kernel failure, chat ownership, background lease retention, and shutdown while preparation/startup is still inspecting state. Existing portable, transport, native Kimi/industrial, desktop selftests and packaged checks remain acceptance gates. This change does not declare new operating systems, native profiles or domains qualified. Local/remote execution choice remains independent of GUI/CLI; remote verification and backend cleanup continue to use their existing contracts.
