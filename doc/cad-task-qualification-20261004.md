# 真实 CAD 任务验收：2026-10-04

本次使用真实模型 **MiniMax-M3**（开启 thinking）、固定 Kimi Code **1.51.0 / SDK 0.1.8**、官方 **FreeCAD 1.1.4**，在 **macOS arm64** 上通过 Harness CLI、Broker 和持久 Domain Runtime 完成同一 chat 的三轮任务。未以固定模型响应替代此次推理。Viewer 另行通过真实 Electron 和独立解压的生产发行目录验证。

## 任务与结果

初始零件为 40 × 20 × 5 mm 的矩形板，孔半径 2 mm，孔位 (10,10)。根目录模型与配方、预览清单具有 SHA-256 绑定。

| 任务 | 真实行为与独立验收 | 耗时 |
| --- | --- | --- |
| 原文“修改零件的形状” | 发起澄清；CLI 保存问题并返回 needs_input，退出码 2；未执行修改，原模型保持不变 | 40.7 秒 |
| 宽度 20 → 30 mm，孔半径 2 → 3 mm；长度、厚度和孔位保持不变 | inspect 后生成新版本；独立回读体积 5858.628330588458 mm³（6000 − 45π），边界 [40,30,5]，一个实体 | 83.4 秒 |
| “继续把刚刚的新版本”改成半径 20 mm 的圆板，厚度 5 mm，半径 3 mm 的孔移至圆心 | 生成新版本；独立回读体积 6141.813637768046 mm³（1955π），边界 [40,40,5]，一个实体；BREP、STEP 与 FCStd 一致 | 136.5 秒 |

第三轮并非一次成功：首次输入缺少充分证据，下一次产生了孔半径不正确的模型（体积 6220.35345410779 mm³），均未被验收。模型读取失败结果后修正，最终通过。失败尝试、诊断与产物保留，不把错误模型记为通过。

每轮检查原件及所有已经通过验证的历史 FCStd 哈希。最后保留并核对 7 个模型文件，包含 Runtime 输入快照；未覆盖原件或上一版本。执行成功文本不作为验收依据。

## 应用内真实任务

随后在实际 Desktop 应用中创建新聊天，使用已配置的同一真实模型和持久示例工程。没有把 CLI 历史导入或伪造成应用事件。

1. 在应用输入原文“修改零件的形状”，模型读取示例配方后展示澄清问题，未修改零件。
2. 在问题中填写：将 60 × 40 × 6 mm 的带凸台安装板加长到 70 mm，保留凸台和全部孔。批准 Runtime 操作后，独立回读体积 19193.89360203543 mm³、边界 [70,40,18]、一个实体，应用显示 Engineering verification passed。
3. 在同一聊天继续要求：将刚刚生成版本的底板改为半径 40 mm、圆心 (30,20) 的圆板，保留凸台和五个孔。Runtime 读取上一轮输出，生成新版本；体积 32553.18307649744 mm³（10362π）、边界 [80,80,18]、一个实体，FCStd/STEP/BREP 一致，独立验收通过。
4. 从实际工程文件树打开该轮新模型，OCCT 显示圆形底板、凸台和孔，10 个曲面，状态 Ready；原件与矩形中间版本保留。聊天与运行诊断留在本地应用。

这一过程中还发现文件树没有随着工业产物生成自动刷新，导致 Viewer 仍打开原件。现已在工业结果和任务完成后刷新当前工程文件列表，并防止异步读取覆盖切换后的工程。CAD Electron selftest 增加真实 Runtime export → 结果事件 → 新模型无需重新打开工程即可出现在文件树的回归。Viewer 本身仍为只读，切换新版本通过 Registry 进行，不覆盖正在查看的原文件。

## 修复与回归

此次真实任务暴露并修复了以下问题：

- 缺少 API 配置时，Desktop 在提交前显示可操作原因、保留输入并恢复按钮，避免只生成 scoped 状态而不启动模型。
- CLI 收到澄清问题时保存 needs_input 状态，不再自动提交空答案；同一 chat 可用下一条明确任务继续。
- 复杂输入增加严格 JSON 字符串传输，保留数组、数字和嵌套对象类型；仍经过原有 Schema、Scope、审批与 Runtime。
- 同工程、同领域、同 State 阶段的明确续接可以沿用已选择能力；当前资源策略继续过滤，明确新任务仍重新匹配。
- Agent 从当前持久 State 获取有界产物路径与哈希，使“刚刚的新版本”具有可读取依据；不从提示词推断工程事实。
- 已启用的外部 MCP 或应用控制在受保护工业任务中按本轮排除，保留用户配置，任务继续经 Domain Runtime。真实 Kimi + FreeCAD 回归使用外部 MCP 启动陷阱验证其没有被启动。

## 可重复运行与覆盖边界

运行入口为 `scripts/qualify-cad-tasks.cjs`。需要真实模型 API、模型 profile、固定 Kimi 和 FreeCAD 可执行路径；在新的输出目录运行。结果保存 report.json、逐轮 JSONL 事件和诊断，密钥不写入仓库。每轮上限 180 秒，超时、未澄清、错误体积、缺少 BREP 或历史文件被覆盖均使验收失败。

本次结果说明此模型在这组任务上能完成有验证的修改及错误恢复；不保证其他模型、任意零件或每次重跑都成功。此前运行也出现过参数类型错误、误读原件和思考超时。模型仍可能耗时较长或需要纠错，界面应显示实际进展和未通过状态。

CI 中的原生任务使用固定模型响应保证重复性，同时执行真实 FreeCAD、独立回读和历史哈希检查。真实 API 任务为单独的显式验收，未加入无密钥的 PR 默认 CI。当前原生 CAD 执行与 Viewer 验收只报告 macOS arm64；不据此声明 Windows/Linux CAD 执行已通过。
